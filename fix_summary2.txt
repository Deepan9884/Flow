I have fixed the root cause of the code generation failures in the GitHub Actions build!

**The underlying issues were:**
1. Isar strictly forbids properties named `id` to be of `String` type. It expects `id` to be an `int` for its primary key system. 
2. Because it was a `String`, the property was being annotated with `@ignore` in Isar. This led Isar's generator to throw a `Constructor parameter does not match a property` error because the required `id` argument in the Freezed constructor couldn't be mapped.
3. In `Task`, the `customFields` property of type `Map<String, dynamic>` was unsupported by Isar and wasn't explicitly `@ignore`d.

**What I changed:**
- Renamed the `id` property to `uuid` across `Task`, `Category`, `ThemeConfig`, and `Subtask` models, and removed the faulty Isar `@ignore` configurations that were breaking the constructor logic.
- Updated all associated Dart logic, state providers, and UI screens to properly reference the new `.uuid` attribute.
- Appended the `@ignore` annotation directly onto the `customFields` property in the `Task` model so Isar can safely bypass it during schema generation.
